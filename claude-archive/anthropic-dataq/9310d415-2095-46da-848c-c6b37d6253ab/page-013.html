  <h1>Spotting Unusual Email</h1>
  <p class="standfirst">Import a mail log, work out what is normal for each recipient, and read one person's timeline with the odd events marked.</p>

  <div class="before">
    <h2>What your file needs</h2>
    <ul>
      <li>One row per email, as CSV, Parquet or JSON.</li>
      <li>A recipient — <b>recipient_id</b>, an address or an account id.</li>
      <li>A timestamp — <b>timestamp</b>, in any format; you will confirm how it reads.</li>
      <li>The thing you want judged — <b>sender_country</b> here, but a domain, an IP block or a subject category works the same way.</li>
    </ul>
    <p style="margin:0.7rem 0 0;font-size:0.94rem;color:var(--muted)">Everything else — subject, sender address, URLs — comes along and shows up on each event. Nothing else is required.</p>
  </div>

  <div class="step">
    <header><span class="n">1</span><h2>Import the file</h2></header>
    <div class="body">
      <p class="do"><b>Datasets → Browse…</b>, pick the file, then <b>Read columns</b>.</p>
      <p>A table appears with one row per column: what was found in the file, what it will be stored as, and what it means. Almost always it is already right and you press <b>Import</b>.</p>

      <div class="seen">
        <span class="tag">Check this one thing</span>
        <p>The <code>timestamp</code> row should say <b>date + time</b> under “Import as”, with the reading shown beside it — something like <code>MM/DD/YYYY HH:MM:SS → 2016-01-04 00:10:37</code>. If it says <b>text</b>, change it: a timestamp stored as text cannot be put on a timeline.</p>
      </div>

      <div class="why">
        <span class="tag">If it asks you a question</span>
        <p>A date like <code>03/04/2016</code> is the 4th of March in most of the world and the 3rd of April in the US. When nothing in your file settles which, that row turns amber and <b>Import</b> stays disabled until you choose. It shows you what each reading would mean, so pick the one that matches where the log came from.</p>
        <p>This only happens when the file genuinely cannot answer it. If any date in your file falls after the 12th of a month, it works it out and does not ask.</p>
      </div>
    </div>
  </div>

    <header><span class="n">2</span><h2>Work out what is normal</h2></header>
    <div class="body">
      <p class="do">On the dataset page: <b>Run an action → Add behavioural features</b>. Put these three lines in the box and press <b>Run</b>.</p>

<pre>event_index()      by recipient_id, sender_country as country_seq
share()            by sender_country            as country_share
days_since_last()  by recipient_id, sender_country as days_since_same_country</pre>

      <div class="scroller">
        <table>
          <thead><tr><th>Line</th><th>Adds a column saying…</th></tr></thead>
          <tbody>

            <tr><td><code>days_since_same_country</code></td><td>days since the last email this recipient got from there. Empty on a first contact.</td></tr>
          </tbody>
        </table>
      </div>

        <span class="tag">Why these three</span>
        <p>“Suspicious” here means two things at once: the recipient has <em>never</em> seen this country, and the country is <em>rare</em> across the whole log. The first is per-person history; the second is a property of the file. They need separate columns because they are separate questions.</p>
      </div>

    </div>

days_since_same_country — no aggregate can produce it

Not awkwardly — structurally. An aggregate emits one row per group, and days-since-previous has a different answer on every event. There's nowhere to put it.

The closest an aggregate gets is Build a feature table by recipient_id, sender_country, which gave 1,043 rows with n, share, rarity, first_seen, last_seen. Attached back, those let you ask "how long has this pair been active" or "how many in total" — properties of the pair, never of the event.

The rule that separates them

  • A property of a value — how common is NG across the log? → aggregate + join. Works, and leaves you a table worth looking at.
  • A property of an event in its sequence — is this the first? how long since the last? → only enrich.features. event_index(), days_since_last(), days_since_first(), and any over 30d window are all in this category.

enrich.features is a transform — it's in the same Run an action dropdown, under Transform, as "Add behavioural features". So both columns in one step is the shorter path; the aggregate route is worth taking when you want the intermediate table for its own sake.
